# iOS 앱 기획 → 와이어프레임 가이드

> Claude와 대화로 아이디어를 구체화하고 와이어프레임까지 도출하는 단계별 프로세스
> "Claude가 먼저 초안, 나는 피드백" 방식으로 설계됨

---

## 결과물 목록

| Step | 결과물 | 형식 | 목적 |
|------|--------|------|------|
| STEP 0 | 컨셉 확정 + 마켓 리서치 | 대화 | 아이디어 → 검증된 컨셉 |
| STEP 1 | 서비스 기획서 | HTML | 시장 분석 + 차별화 전략 문서화 |
| STEP 2 | 유저 저니 + 와이어프레임 | MD | 실제 흐름 + 화면 구조 |
| STEP 3 | 디자인 시스템 | HTML | 컬러, 타이포, 컴포넌트 |
| STEP 4 | 기술 스택 문서 | MD | 개발 방식 결정 |
| STEP 5 | 개발 스펙 문서 | MD | 구현 준비 완료 |

---

## 전체 플로우

```
STEP 0   컨셉 인터뷰 + 마켓 리서치
   ↓     (컨셉 확정 후 다음 단계)
STEP 1   서비스 기획서 (HTML)
   ↓
STEP 2   유저 저니 + 와이어프레임 (MD)
   ↓      ├ 2-1: Journey Phase 구조화 초안
   ↓      ├ 2-2: CRITICAL 포인트 Q&A (1개씩)
   ↓      ├ 2-3: Journey 확정본 정리
   ↓      ├ 2-4: 화면별 디테일 (1개씩)
   ↓      └ 2-5: ASCII 와이어프레임 MD 작성
   ↓
STEP 3   디자인 시스템 (HTML)
   ↓
STEP 4   기술 스택 결정 (MD)
   ↓      ├ 요구사항 체크리스트 입력
   ↓      ├ 최적 기술 추천 + 비용 예상
   ↓      └ 최종 스택 확정
   ↓
STEP 5   개발 스펙 문서 (MD)
   ↓
구현 시작 (화면별)
```

---

## STEP 0 — 컨셉 인터뷰 + 마켓 리서치

**목적**: 아이디어를 다각도로 검증하고 핵심 컨셉 확정

**프롬프트**:
```
[서비스 아이디어 1~3줄]

이 아이디어로 iOS 앱을 만들려고 해.

먼저 컨셉을 충분히 이해하고, 마켓 리서치를 한 다음에 아래를 해줘:
- 컨셉 수정/보완 제안
- 차별화 포인트 강화 (시장에 없는 것 찾기)
- 기능 고도화 제안
- 네이밍/포지셔닝 제안

대화 방식으로 진행해줘.
한 번에 다 하지 말고, CRITICAL한 결정 포인트가 있으면 하나씩 물어봐줘.
```

**Claude 행동 규칙**:
- 컨셉을 자신의 말로 재해석해서 먼저 확인
- 시장 공백(White Space) 찾아서 명확히 제시
- 경쟁사와의 차이가 명확해질 때까지 대화 반복
- 컨셉 확정 선언 후 STEP 1으로 이동

---

## STEP 1 — 서비스 기획서

**목적**: 검증된 컨셉을 시장 분석과 함께 문서화

**프롬프트**:
```
확정된 컨셉을 기반으로 서비스 기획서를 만들어줘.

포함 내용:
- 서비스 개요 (컨셉, 슬로건, 포지셔닝 한 줄)
- 경쟁사 분석 (5개 이상)
  - 강점 / 약점 / 우리와의 차이
- 시장 규모 (TAM / SAM / SOM)
- 타겟 페르소나 3인 (JTBD 기반)
- 핵심 기능 정의 (MVP vs 후순위)
- 수익 모델 옵션 + 추천
- 개발 로드맵 (Phase 1~3)
- 리스크 분석

보기 좋은 HTML 파일로 만들어줘.
파일명: [app-name]-planning.html
```

---

## STEP 2 — 유저 저니 + 와이어프레임

**목적**: 실제 사용 흐름을 대화로 구체화하고 ASCII 와이어프레임으로 시각화

**프롬프트**:
```
기획서를 바탕으로 유저 저니와 와이어프레임을 잡아줘.

진행 방식:
- Claude가 먼저 초안 제시, 나는 피드백만
- CRITICAL 결정은 한 번에 하나씩 질문
- 모르겠으면 솔직히 말해도 됨 (Claude가 장단점 설명 후 추천)

순서:
[2-1] 전체 유저 Journey를 Phase로 구조화해서 초안 제시
[2-2] CRITICAL 결정 포인트 하나씩 Q&A
      (각 질문에 답하면 다음 질문으로 진행, 절대 여러 개 한꺼번에 묻지 마)
[2-3] 확정된 내용으로 전체 Journey 정리본
[2-4] 탭/화면별로 하나씩 디테일 정의
      (각 화면: 초안 제시 → 피드백 → 확정 후 다음 화면)
[2-5] 모든 화면 확정 후 ASCII 와이어프레임 MD 파일 작성

ASCII 와이어프레임 형식 예시:
┌─────────────────────────┐
│ 화면 이름               │
├─────────────────────────┤
│ [상단 영역]              │
│  타이틀        버튼 [+] │
├─────────────────────────┤
│ [메인 콘텐츠]            │
│  ┌───────────────────┐  │
│  │ 항목 1            │  │
│  └───────────────────┘  │
│  ┌───────────────────┐  │
│  │ 항목 2            │  │
│  └───────────────────┘  │
├─────────────────────────┤
│ [하단 탭바]              │
│  홈  |  기록  |  설정   │
└─────────────────────────┘

지금 바로 2-1부터 시작해줘.
파일명: [app-name]-wireframe.md
```

**Claude 행동 규칙**:
- 2-2는 반드시 1개씩만 질문 (한꺼번에 여러 개 금지)
- 각 질문에 옵션 A/B/C 형태 + 추천 명시
- 2-4는 메인 탭부터 순서대로, 각 화면 확정 후 다음으로
- 2-5 완성 후 MD 파일 저장

---

## STEP 3 — 디자인 시스템

**목적**: 구현 전 앱의 시각적 정체성 확정 (이 단계를 건너뛰면 나중에 디자인이 뒤죽박죽됨)

**프롬프트**:
```
와이어프레임 확정됐어.
이제 디자인 시스템을 잡아줘.

포함 내용:
- 앱 아이덴티티
  - 브랜드 키워드 3개
  - 무드 방향 (예: 미니멀 / 따뜻함 / 프리미엄)
- 컬러 시스템
  - Primary / Secondary / Neutral 팔레트 (hex 값 포함)
  - 다크모드 대응 여부
  - iOS 접근성 기준 (WCAG AA 이상)
- 타이포그래피
  - iOS SF Pro 기반 사이즈 스케일
  - 제목 / 본문 / 캡션 / 레이블 스타일
- 간격 시스템 (spacing scale: 4pt 단위)
- 아이콘 스타일 (SF Symbols 기반 vs 커스텀)
- 핵심 컴포넌트 정의
  - 버튼 (Primary / Secondary / Destructive)
  - 카드 컴포넌트
  - 입력 필드
  - 탭바 / 네비게이션바
  - 빈 상태(Empty State) 디자인
- 애니메이션 원칙 (속도/곡선/톤)

보기 좋은 HTML 파일로 만들어줘.
파일명: [app-name]-design-system.html
```

---

## STEP 4 — 기술 스택 결정

**목적**: 서비스 요구사항에 맞는 최적 기술 선택 (절대 이전 프로젝트 스택 복붙 금지)

**프롬프트**:
```
기술 스택을 결정하려고 해.
아래 체크리스트 채워줄게.

--- 요구사항 체크리스트 ---
필요한 기능:
□ 로그인 / 회원가입
□ 위치 기반 기능
□ 사진 / 카메라
□ 음성 / 오디오
□ AI 기능 (Claude API 등)
□ 실시간 동기화
□ 오프라인 지원
□ 푸시 알림
□ 결제 / 구독 (In-App Purchase)
□ 소셜 기능 (공유, 팔로우 등)
□ iOS 홈화면 위젯
□ Apple Watch 연동
□ 기타: ___

플랫폼: iOS 전용 / iOS + Android / 웹 포함
개발 방식: 혼자 / 팀 / 외주
개발 경험: 초급 / 중급 / 고급

--- 체크 결과 ---
[여기에 입력]

요청:
1. 기능별 최적 기술/API 추천 (이유 + 대안 포함)
2. 비용 발생 항목 예상 비용 명시
3. 최종 기술 스택 표로 정리
4. 함정 / 주의사항 미리 알려줘

MD 파일로 저장해줘.
파일명: [app-name]-tech-stack.md
```

---

## STEP 5 — 개발 스펙 문서

**목적**: 화면별 구현 준비 완료 상태 문서화

**프롬프트**:
```
기술 스택까지 확정됐어.
이제 개발 스펙 문서를 만들어줘.

포함 내용:
- 화면 목록 & 각 화면의 역할
- 화면 간 네비게이션 구조 (스택 / 탭 / 모달)
- 각 화면의 State 정의
  - 필요한 데이터
  - 로딩 / 에러 / 빈 상태
- API 호출 시점 정의
- 외부 서비스 연동 포인트
- 구현 우선순위
  - MVP Phase 1 (출시 필수)
  - 고도화 Phase 2
  - 미래 기능 Phase 3
- 개발 시작 순서 추천

확정된 기술 스택: [STEP 4 결과 붙여넣기]

MD 파일로 저장해줘.
파일명: [app-name]-dev-spec.md
```

---

## 팁

**2-2 Q&A에서 모르겠으면 솔직히 말해라.**
Claude가 장단점 설명 후 추천해줌. 틀려도 나중에 바꿀 수 있음.

**STEP 3 (디자인 시스템)을 건너뛰지 마라.**
와이어프레임 직후 코드로 가면 나중에 디자인이 뒤죽박죽됨.
이 단계를 밟는 것만으로 최종 퀄리티가 2배 달라짐.

**기술 스택은 항상 새로 결정.**
서비스마다 요구사항이 달라. 특히 비용 발생 API (음성, 이미지, AI)는 미리 파악 필수.

**결과물 파일 이름 규칙:**
```
[app-name]-planning.html
[app-name]-wireframe.md
[app-name]-design-system.html
[app-name]-tech-stack.md
[app-name]-dev-spec.md
```
